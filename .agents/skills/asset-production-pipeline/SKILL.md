# Asset production pipeline

## Required metadata

Before an asset can ship, record:

- stable asset ID and semantic purpose;
- author/source and provenance;
- license/reuse constraints;
- source file location;
- physical or artistic units;
- color space;
- dimensions, vertex/triangle count, and texture channels;
- uncompressed and delivered byte size;
- optimization commands and tool versions;
- quality-tier usage and fallback.

Use the schema in `docs/templates/asset-manifest.schema.json`.

## Procedure

1. Read `docs/workflows/asset-pipeline.md`.
2. Confirm ownership and reuse rights before editing.
3. Normalize Blender scene scale, origin, transforms, names, materials, and color management.
4. Export glTF 2.0 binary.
5. Inspect before optimizing.
6. Apply Meshopt geometry compression.
7. Convert GPU textures to KTX2:
   - UASTC for normal/data maps;
   - ETC1S for suitable perceptual color maps.
8. Produce alpha-capable AVIF and WebP fallback for transparent 2.5D assets.
9. Generate a low-cost poster/fallback.
10. Verify output visually in the real runtime, not only in Blender.
11. Check byte size, decode cost, GPU memory, alpha edges, color shifts, mipmaps, and mobile behavior.
12. Update the asset manifest in the same change.

## Blocking defects

- no provenance or license;
- unapplied transforms;
- accidental cameras/lights;
- excessive materials or draw calls;
- oversized textures without tiering;
- normal/data maps treated as sRGB;
- alpha halos or premultiplication mismatch;
- production files generated by undocumented manual steps;
- source authoring files committed outside the agreed LFS/external-source policy.

## Output contract

Report source and output paths, exact commands/tool versions, before/after metrics, runtime screenshots, fallback, and manifest changes.
